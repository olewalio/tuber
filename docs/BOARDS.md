# Борды залёта («Что залетело»)

Одна самодостаточная HTML-страница: **три доски подряд** — X, YouTube и
Телеграм (сетка квадратных карточек с самыми виральными материалами окна), плюс
три раздела ТЗ-4 — **«Темы окна»**, **«ИИ-инструменты»** и **«Залетевшие
сюжеты»** — и PNG-графики. CSS встроен, внешних CDN/шрифтов/скриптов нет;
графики — обычные локальные `<img src="имя.png">` рядом со страницей.

## Что это

* `tools/build_boards.py` — генератор страницы (только stdlib + код проекта).
* `tools/build_charts.py` — генератор трёх PNG-графиков (matplotlib).
* `reports/boards/index.html` — готовая страница.
* `reports/boards/{topics_daily,topics_bar,platform_daily}.png` — графики.
* `reports/boards/boards.json` — те же данные для отладки/повторного
  использования (карточки, разделы ТЗ-4, числа «рассмотрено / прошло полы»).
* `deploy/boards.conf` — блок nginx для отдачи страницы (basic-auth,
  ограничение частоты, `noindex`), по образцу HypeParser.
* `tests/test_boards.py`, `tests/test_charts.py` — приёмочные тесты.

## Откуда числа

Отбор — **тот же**, что в полном отчёте (`tuber/analysis/report.py`), генератор
не пишет собственный SQL:

| Доска | Пул | Метрика (главное число) | База |
|-------|-----|--------------------------|------|
| X | `viral_x_pool` | лайки ÷ медиана лайков своего автора | медиана автора |
| YouTube | `viral_youtube_pool` | просмотры ÷ медиана просмотров своего канала | медиана канала (вторая строка — подписчики и охват) |
| Телеграм | `viral_tg_pool` | просмотры ÷ `source_baseline.median_views` | медиана канала |

Публичные обёртки `viral_x_pool` / `viral_youtube_pool` / `viral_tg_pool` и
`viral_x_ratio_map` добавлены в `report.py` именно для этого: генератор берёт
пулы и нормы отчёта, а не дублирует SQL и медианы.

Доска — это **топ по кратности**, а не только позиции, прошедшие полы отчёта.
Поэтому: кандидаты = пул окна с непустыми нужными метриками; сортировка по
кратности (убывание); не больше 2 карточек на канал/автора (как в отчёте); на
доску — не больше `--limit` карточек.

В шапке каждой доски честно указано, сколько материалов **рассмотрено** и
сколько **прошло полы** отчёта (числа из статистики отбора).

## Разделы ТЗ-4 и графики

Три раздела идут перед досками (порядок: «Темы окна» → «ИИ-инструменты» →
«Залетевшие сюжеты» → график поступления → три доски). Их окно —
**календарное**: полночь `сегодня − days` UTC (у досок окно осталось
«катящимся», как в отчёте).

| Раздел | Данные | Что показывает |
|--------|--------|----------------|
| Темы окна | `classification.topic` (без NULL/пустого/«(без темы)») | топ-10 тем по объёму; сюжеты — большинство участников `story_member` с этой темой; ускорение = окно ÷ предыдущее такое же окно (пустое → прочерк); порядок — по ускорению |
| ИИ-инструменты | `topic = 'ИИ-инструменты для обычных людей'` | топ-10 по кратности, полы и нормы — из `report.py` (YouTube/Telegram — те же отборщики; X — `viral_x_ratio_map` + константы полов); разбивка по `subtopic` за 7 суток |
| Залетевшие сюжеты | `story` + `story_member` | топ-10 окна по `source_count`, затем `content_count`; заголовок — `title_ru` канонического (иначе оригинал); тема — большинство участников; опережение `lead_time_min` печатается в часах |

`story.topic` в базе пустое у всех строк и **не используется** — тема сюжета
считается большинством голосов участников. Живой LLM-перевод в разделе сюжетов
не включается: берётся только русский из базы (`classification.title_ru`), иначе
оригинал как есть.

## Честность чисел

* Только чтение базы (`file:…?mode=ro`); генератор **в сеть не ходит и LLM не
  зовёт**. Русское описание X берётся тем же путём, что в отчёте
  (`classification.title_ru`/`summary_ru` → кэш `report_text`), плюс перевод
  «соседней» строки того же текста по `text_hash` (`report.x_ru_hash_map`,
  `classification` → `classify_cache`); живой перевод жёстко выключен
  (`allow_live=False`). Нет русского — показывается оригинал.
* Нет подписчиков или медианы — кратность не выдумывается (в карточке
  прочерк), и такая карточка в топ по кратности не лезет (сортируется в конец).
* Пустое предыдущее окно у темы — прочерк ускорения, ноль не подставляется;
  нет данных по подтеме — прочерк, подтема не выдумывается.
* Даты — UTC из базы, подписи по-русски; в шапке — время сборки в UTC и МСК и
  дата последнего замера метрик.

## Графики (matplotlib)

`tools/build_charts.py` (только чтение базы, `Agg`) кладёт рядом со страницей
три PNG: `topics_daily.png` (динамика топ-5 тем по дням), `topics_bar.png`
(топ-12 тем по числу материалов) и `platform_daily.png` (поступление по
платформам X/YouTube/Telegram). Подписи осей и легенд русские, шрифт крупный
(страница читается с телефона), эмодзи нет, числа на осях целые и без
экспоненты; пустой день — честный ноль; заголовки берут фактический диапазон
дат окна. На странице — обычные локальные `<img src="имя.png" alt="…">`
(не base64).

## Как пересобрать

```bash
# страница: окно 10 дней, 50 карточек на доску, боевая база и путь по умолчанию
python3 tools/build_boards.py

# страница явно
python3 tools/build_boards.py --days 10 --limit 50 \
    --out reports/boards/index.html --db data/tuber.db

# графики рядом со страницей
python3 tools/build_charts.py --days 10 --out reports/boards
```

Ключи страницы: `--days` (10), `--limit` (50), `--out`
(`reports/boards/index.html`), `--db` (боевая база по правилам
`tuber/config.py`). Ключи графиков: `--days` (10), `--out`
(`reports/boards`), `--db`.

Генератор печатает путь к странице, её размер, время сборки, число карточек по
каждой платформе и число тем/сюжетов/инструментов.

## Как отдать в веб

Блок nginx — `deploy/boards.conf` (инструкция в комментариях файла): нужен
файл паролей `/etc/nginx/.htpasswd_boards` и зона `limit_req` из
`/etc/nginx/conf.d/boards-zone.conf`. Схема та же, что у HypeParser. Фактически
страница и PNG отдаются из `/var/www/boards/` (alias в
`/etc/nginx/snippets/hype-shared.conf`).

Крон-скрипт `/root/.hermes/scripts/tuber_boards_build.sh` пересобирает страницу
**и графики** и копирует `index.html` + три PNG в `/var/www/boards/`. Режим
сторожевой: при успехе молчит, при сбое пишет в чат и выходит с кодом 1.


## Как выключить

* убрать `include /root/tuber/deploy/boards.conf;` из `server{}` и
  `systemctl reload nginx`;
* при необходимости удалить `/etc/nginx/conf.d/boards-zone.conf`;
* удалить `reports/boards/` с собранной страницей.
