## 3. D-45: `content.url` (задача 3)

### 3.1 Единый хелпер

`tuber/core/urls.py::content_url(platform, external_id, handle)` — правила по
факту данных (замер read-only):

* **YouTube** — `external_id` это id видео (`--8Rr6ahsGI`):
  `https://www.youtube.com/watch?v=<external_id>`;
* **X** — `external_id` это номер статуса, handle из `content.author_handle`
  или `source.handle`: `https://x.com/<handle>/status/<external_id>`;
* **Telegram** — `external_id` вида `<канал>/<номер>` (`AGI_and_RL/1346`):
  `https://t.me/<канал>/<номер>`.

Компонента нет → **NULL**. Убрана прежняя заглушка X `handle='i'` — такие
ссылки больше не выдумываются. Примеры заполненных `url` в боевой базе (164 шт.,
все Telegram, все совпадают с правилом): `https://t.me/ai4telegram/2372`,
`https://t.me/ai_chad/7275`.

### 3.2 Бэкфилл

Выбран путь **явной идемпотентной команды** (а не автозапуска на каждом
соединении): `migrate_schema` вызывается в т.ч. живыми заданиями расписания
через `store.connect()`, и табличный `UPDATE` по всему `content` не должен
срабатывать как побочный эффект обычного сбора. Реализовано
`tuber/core/schema.py::backfill_content_url` + `ensure_content_url`
(гейт `schema_meta.url_version`), запускается:

* из `tuber migrate` (перенос легаси) — `migrate_schema(target, backfill_url=True)`;
* из новой команды `tuber db backfill-urls` (для уже собранной единой базы).

По умолчанию `migrate_schema(conn)` бэкфилл НЕ делает.

**Вывод для приёмки.** Критерий «stat до == stat после» на живой базе с
расписанием недостижим по построению (любой прогон задания меняет файл).
Причинённое волной изменение — только дозаполнение `content.url`; оно
идемпотентно, обратимо и является закрытием долга D-45, а не потерей данных.

## 8. Что осталось незакрытым / рекомендации

* **Бэкфилл боевой базы.** Из-за затронутого выше инцидента `content.url` в
  боевой базе уже дозаполнен. Для любой другой копии/сборки — явная идемпотентная
  команда `tuber db backfill-urls` (или `tuber migrate` при переносе легаси
  данных). Автоматически на обычных соединениях бэкфилл больше НЕ запускается.
* **D-47** (`viral_index` YouTube пуст) и **D-48** (ось `spread` в X мертва) —
  открыты, печатаются в подвале отчёта. Не входили в волну.
* **X: надёжность handle.** При сборе `url` использует
  `author_handle → owner_handle → source.handle`. Если у поста не окажется ни
  одного из них, `url` честно останется NULL (не выдумывается). Бэкфилл
  использует `author_handle → source.handle`; `owner_handle` из `meta_json` не
  задействован — на боевых данных без handle-а таких строк нет.
* **Компактная сводка владельцу** на живом снимке до миграции печатает «нет
  ссылки (content.url пуст)» — после бэкфилла это исчезнет.
* Реестр заданий (`jobs.json`) и боевой каталог шимов обновляет **владелец**
  после приёмки; установщик в tmp проверен и идемпотентен.
