# ТЗ-34. Секция «Локальные выбросы» — виральность относительно своего канала/автора

Дата: 18.09.2026. Модуль: `tuber/analysis/report.py` (объединённая выдача, ТЗ-5).
Исполнитель: jCode (--local). Приёмка: владелец (Hermes) на копии боевой базы.

## 1. Проблема (жалоба владельца, подтверждена измерением)

Владелец: «у тебя в выборку попадают только посты с млн просмотрами топ-аккаунтов,
а виральные посты полезные, которые дают тысячи просмотров с шикарными охватами
локальными не попадают».

Причина в коде, а не в данных:

* секция 1 (YouTube) ранжирует по АБСОЛЮТНЫМ `views_per_day` с отсечкой показов
  50 000 (ru — 10 000) → в топ-15 попадают только крупные каналы;
* секция 2 (X) ранжирует `ORDER BY cl.likes DESC LIMIT 15` → только топ-аккаунты
  (@OpenAI, @sama, @elonmusk);
* секция 3 (Telegram) нормирует внутри канала, но отбирает каналы по значимости,
  а не по превышению своей обычной базы.

Материал с локальным всплеском (малый канал, кратно больше обычного) не попадает
в выдачу НИКОГДА, потому что по абсолюту он всегда проигрывает топ-аккаунтам.

## 2. Измерение (боевая база 18.09.2026, окно 10 суток, только чтение)

Кандидаты при полах «просмотры ≥ 3 000, в сутки ≥ 300, у канала ≥ 5 видео в окне,
кратность ≥ 5 к своей базе»: **356 материалов у 235 каналов** (YouTube).
X (лайки ≥ 200, у автора ≥ 5 постов, кратность ≥ 5): **24 у 14 авторов**.
Telegram (просмотры ≥ 1 000, у канала ≥ 3 поста, кратность ≥ 3): **43 у 37 каналов**.

## 3. Что сделать

### 3.1 Константы (в блоке констант модуля, с комментарием-обоснованием)

```python
# --- Локальные выбросы (ТЗ-34) ------------------------------------------------
#: Полы и кратности — из замера по боевой базе 18.09.2026 (см. docs/TZ-34).
LOCAL_YT_MIN_VIEWS = 3_000
LOCAL_YT_MIN_VPD = 300
LOCAL_YT_MIN_CHANNEL_VIDEOS = 5
LOCAL_YT_RATIO = 5.0
LOCAL_YT_PER_CHANNEL = 2
LOCAL_YT_LIMIT = 15
LOCAL_X_MIN_LIKES = 200
LOCAL_X_MIN_AUTHOR_POSTS = 5
LOCAL_X_RATIO = 5.0
LOCAL_X_PER_AUTHOR = 2
LOCAL_X_LIMIT = 15
LOCAL_TG_MIN_VIEWS = 1_000
LOCAL_TG_MIN_CHANNEL_POSTS = 3
LOCAL_TG_RATIO = 3.0
LOCAL_TG_PER_CHANNEL = 2
LOCAL_TG_LIMIT = 15
```

`COMPACT_LIMIT`: 3500 → **3900** (лимит Telegram 4096; без поднятия новый раздел
не влезает, а справедливая раздача бюджета начинает резать описания соседних
разделов). Комментарий обоснования в коде обязателен.

### 3.2 Метрика

Кратность = значение материала ÷ **медиана** значений ЭТОГО ЖЕ канала/автора за
окно (`statistics.median`, не среднее: один выброс сносит среднее и «съедает»
сам себя). Значение:

* YouTube — `views_per_day` последнего снимка с `interval_quality='ok'`
  (тот же подзапрос, что в `youtube_items`);
* X — `likes` из `content_latest` (репосты исключены, `is_repost=0`);
* Telegram — `views` из `content_latest`.

Материал попадает в секцию, если выполнены ВСЕ условия: абсолютный пол пройден
И число материалов канала/автора в окне ≥ минимума И кратность ≥ порога.

Сортировка: кратность убыв., при равенстве — абсолют убыв. Не более
`LOCAL_*_PER_*` позиций с одного канала/автора (иначе один канал займёт весь топ).
Итог — не более `LOCAL_*_LIMIT`.

### 3.3 Формат строки (как у секций 1–3, `CompactItem`)

Обязательно в строке: название/текст, канал (у YouTube — ещё подписчики),
абсолют, кратность к МЕДИАНЕ своего канала, сама медиана («обычно N»), ПОЛНАЯ
ссылка. Для YouTube дополнительно `просмотров на подписчика` при `source.subs>=100`;
если подписчиков нет — писать «подписчиков: нет данных» (не выдумывать).

Запрещено: выдумывать ссылки/handle, печатать кратность без медианы (цифра без
базы нормировки не проверяема).

### 3.4 Полный отчёт (`build`)

Новая секция после секции 4: «5. Локальные выбросы — всплески относительно своего
канала/автора.» Строка правил: окно, полы, пороги кратности, «значимость
нормируется на медиану СВОЕГО канала, между каналами кратности сравнимы».
Плюс строка статистики: «рассмотрено N материалов у M каналов, прошли полы и
кратность K, показано L (не более 2 на канал)».

### 3.5 Компактная сводка (`build_compact`)

Новый раздел «4. Локальные выбросы — всплески у малых каналов/авторов:».
Сквозной сюжет переезжает на «5.» (строку номера поправить, не сломав текст).
Бюджет делится тем же алгоритмом (резерв 1 пункт + round-robin).

**Дедупликация (обязательно):** пункт локальной секции НЕ показывать, если этот же
материал уже показан в разделах 1–3 (сравнение по `content_id`), иначе бюджет
тратится дважды на одну и ту же публикацию. Для этого `CompactItem` получает
необязательный аргумент `content_id: int | None = None` (по умолчанию None —
существующие вызовы не меняются), а `build_compact` собирает id уже показанных
пунктов и фильтрует локальные.

### 3.6 Тесты (`tests/analysis/test_report_local_outliers.py`, новый файл)

Минимум 8 проверок на синтетической базе (фикстуры как в соседних тестах report):

1. YouTube: канал с 6 видео (медиана 100 в сутки) + одно видео 900 в сутки с
   просмотрами 5 000 → попадает; кратность в строке = 9.
2. YouTube: видео с кратностью 2 (ниже `LOCAL_YT_RATIO`) → не попадает.
3. YouTube: видео с 50 000 в сутки, но просмотрами 1 500 (ниже пола) → не попадает.
4. YouTube: канал с 3 видео в окне (меньше `LOCAL_YT_MIN_CHANNEL_VIDEOS`) → не попадает.
5. Не более `LOCAL_YT_PER_CHANNEL` видео с одного канала в выдаче.
6. X: автор с 5 постами (медиана 50 лайков) + пост 800 лайков → попадает; пост
   150 лайков (ниже пола) → не попадает; автор с 3 постами → не попадает.
7. Telegram: канал с 3 постами (медиана 500 просмотров) + пост 3 000 → попадает
   (кратность 6 ≥ 3); пост 900 просмотров → не попадает (пол 1 000).
8. `build_compact`: локальный пункт, дублирующий показанный в разделе 1, в сводку
   не попадает; размер сводки ≤ `COMPACT_LIMIT` байт UTF-8.
9. `stats` секции: `considered`/`above`/`shown` сходятся с числом строк.
