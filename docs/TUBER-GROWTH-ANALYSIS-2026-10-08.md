## 2. Где каналы не дохватывают (дыры охвата)

### 2.1. YouTube — обход застрял
- Реестр: 2 174 канала под обход uploads.
- Порция: 400 каналов/сутки.
- Цикл обхода: ~5,4 суток. Но тесты сбрасывают курсор — покрытие падает до 18% (400/2174).
- Язык не записан у 3 723 из 13 236 каналов — фильтр по языку не работает.

### 2.2. X — метрики не собираются
- Nitter даёт только 20 постов без лайков/ретвитов.
- Нет baseline — невозможно оценить, взлетел ли пост относительно нормы автора.
- 1 389 источников — мало для глобального потока X.

### 2.3. Exchange feed засорен гигантами
- 2 297 кандидатов из tuber-os (1 166 Telegram, 1 131 X).
- Топ упоминаний: NDTV 370, SkyNews 259, KhabarGaon 249, RajShamani 229 — все гиганты-новостники.
- Фильтр по подписчикам/размеру отсутствует — гиганты проходят.

### 2.4. Нет автодискавери из «залетевшего» контента
- Когда пост попадает на доску (залетает), мы не извлекаем хендлы из его текста/ссылок.
- Не проверяем, кто процитировал/ответил — это естественный путь расширения.

## 4. Предложения (без излишнего усложнения)

### 4.1. Критично: заполнить baseline для YouTube и X из существующих данных
**Зачем:** без baseline нельзя понять, растёт ли канал.

**Как:** у нас уже есть `content_latest` с просмотрами/лайками. Нужен SQL-запрос, который для каждого канала считает медиану последних N видео/постов и записывает в `source_baseline`.

**Результат:** получим для всех платформ метрику «норма канала», как у Telegram.

### 4.2. Критично: исправить обход YouTube (увеличить 400 → 2 174 и защитить курсор)
**Зачем:** 82% каналов не проверяются вообще.

**Как:** ТЗ-6 уже в очереди. Увеличить порцию до всего реестра (2 174), защитить курсор от тестов.

### 4.3. Автодискавери из «залетевшего» контента
**Зачем:** естественный путь расширения — когда пост залетает, извлекать хендлы из его текста.

**Как:** после сбора «залетевших» постов запускать тот же `discover`-модуль, но не на все посты, а только на те, которые попали на борду.

**Результат:** новые каналы из цитат/упоминаний будут автоматически попадать в реестр.

### 4.4. Отсечь гигантов от exchange feed
**Зачем:** сейчас в фид попадают NDTV (370 упоминаний), SkyNews (259) — новостные гиганты, не дающие трендового контента.

**Как:** добавить в фильтр bridge порог `max_subs` (500 000 или 1 000 000) или `max_mentions` для отсечения гигантов-новостников.

### 4.5. Использовать trusted_indegree для приоритета новых кандидатов
**Зачем:** каналы с `trusted_indegree >= 2` уже получили «одобрение» от доверенной сети.

**Как:** при импорте кандидатов из exchange feed сначала брать тех, кто упоминается в залетевших постах (имеет ненулевой `trusted_indegree`).

### 4.6. Растущие темы — искать каналы по темам
**Зачем:** если тема «агенты и автоматизация» растёт — нужно больше каналов по этой теме.

**Как:** использовать существующий поиск X (Nitter search) по трендовым темам, извлекать авторов постов и добавлять их в реестр.

## 5. Приоритет реализации

1. **Срочно (эффект за 1 день):** заполнить baseline для YouTube/X из существующих данных — один SQL + Python-скрипт.
2. **Срочно (1-2 дня):** исправить обход YouTube (ТЗ-6) — уже в очереди.
3. **Неделя:** автодискавери из залетевшего + фильтр гигантов в exchange.
4. **Месяц:** тематический поиск каналов по растущим темам.

---

## 6. Ожидаемый эффект

- **+50-100 новых каналов/месяц** из автодискавери залетевшего.
- **Покрытие YouTube: 18% → 100%** после исправления курсора.
- **Больше «свежего» контента** — благодаря тематическому поиску.
- **Меньше гигантов-новостников** — больше нишевых каналов.
