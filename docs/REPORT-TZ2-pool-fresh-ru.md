# Отчёт ТЗ №2: пул кандидатов и русские описания X в «Новом за сутки»

Дата: 20.09.2026. Модуль: `tuber/analysis/report.py`, тесты:
`tests/analysis/test_tz2_digest_pool_and_fresh_ru.py`. База: коммит `300e3ba`.

## 1. Дефект 1: память выдачи схлопывала разделы

Причина подтверждена: выборка кандидатов была ограничена узким `LIMIT`
(`X_CANDIDATE_LIMIT = 150`, YouTube — по лимиту раздела), поэтому после исключения
показанных позиций добирать было нечем и разделы схлопывались до 1–3 позиций.

Правка (§1.1–§1.4):

- введены `CANDIDATE_FACTOR = 8` (env `TUBER_CANDIDATE_FACTOR`) и
  `candidate_pool(section_size) = max(section_size * K, 200)`;
- порядок обработки: широкая выборка → порог/дедуп (в SQL) → исключение
  показанных за `DIGEST_MEMORY_DAYS` → кэп на автора → обрезка до размера раздела
  (`_cap_items_per_key` применяется к пунктам ПОСЛЕ фильтра памяти);
- исчерпание пула теперь честно печатается: пустое состояние —
  «все позиции показывались в предыдущие N суток (пул исчерпан)», частичное —
  «часть позиций показывалась… пул исчерпан, в пуле осталось X из Y»;
- раздел «Виральные» печатается, если пул непуст, даже когда весь пул показывался
  ранее (раньше исчезал молча);
- в `digest_sent` пишутся только фактически напечатанные позиции (`record_sink`
  заполняется из `s["shown"]`).

## 2. Дефект 2: английские описания X в «Новом за сутки»

Логика описания X вынесена в общий помощник `_x_description_from`
(`summary_ru` → `title_ru` → кэш `report_text` → живой перевод → сырой текст) и
`_x_desc_fields` (отложенный перевод). `new_today_items` теперь применяет тот же
помощник через `_apply_deferred_x_descriptions` к позициям, реально попавшим в
вывод (`[:FRESH_LIMIT]`), а не только `x_items`. При `TUBER_RU_DESC=0` поведение
прежнее — сырой текст. Дублирования логики нет.

## 3. Приёмка: двойной прогон на копии боевой базы

Копия создана через `sqlite3` backup API, база боевая не изменялась. Команда:
`TUBER_DB=<копия> python3 -m tuber report --compact --save --out /tmp/tz2-final/outN`.

| Виральные | показано 3, скрыто 3 | показано 0, честная строка «все позиции показывались в предыдущие 3 суток (пул исчерпан)», скрыто 6 |
| Новое за сутки | показано 10 | показано 10 |

- `digest_sent`: 41 строка после прогона 1 (youtube 14, x 14, viral 3, fresh 10),
  81 после прогона 2 (youtube 29, x 29, viral 3, fresh 20).
- Пересечение позиций прогонов: 0 (43 и 40 ссылок).
- Признаки успеха: (а) размеры разделов во втором прогоне НЕ меньше штатных
  (YouTube 15 ≥ 14, X 15 ≥ 12, Новое 10); (б) пересечение 0; (г) при исчерпании
  пула — честная строка, а не пустой/исчезнувший раздел.

### Прогон B (кэш `report_text` прогрет для 4 свежих X-постов — заглушка живого перевода)

Размеры разделов и память те же. Дополнительно проверено (в):

- X-позиции раздела «Новое за сутки» во втором прогоне печатаются по-русски
  (например, `@DavidSacks: Дэвид Сакс: благодаря лидерству Трампа в ИИ создан
  миллион рабочих мест…`, `@paulg (в ленте @elonmusk): Пол Грэм…`);
- при `TUBER_RU_DESC=0` те же позиции снова сырым английским текстом.

Ограничение песочницы: живого перевода нет (нет `DEEPSEEK_API_KEY`), поэтому в
прогоне A описания X остаются английскими; путь «кэш → русское описание»
подтверждён в прогоне B и тестами (заглушка переводчика без сети).
