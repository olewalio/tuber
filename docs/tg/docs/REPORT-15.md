# ТЗ-15. Отчёт: «сбор не взял ни одного канала» больше не немой

Дата: 15.09.2026, ~22:15 MSK. Репозиторий: `/root/tuber-telegram`.
База: принята работа ТЗ-14 (коммит `f1fdebe`).

## Что было (дефект)

На живом файле:

```
TG_TEST_JSON='{"channels_ok":0,"channels_fail":0,"errors":0,"posts_new":0,"posts_upd":0}' bash scripts/cron_collect.sh
→ пустой stdout
```

При 155 каналах в реестре прогон с `channels_ok=0`, `channels_fail=0` и без ошибок
неотличим для владельца от штатной тишины. Это либо поломка списка каналов, либо
мгновенный обрыв по дедлайну — и владелец об этом не узнавал. Тот же класс дефекта,
что чинили в ТЗ-14 (молчание вместо сигнала).

## Что стало

В `scripts/cron_collect.sh` добавлена четвёртая ветка `elif ok == 0`. Порядок ветвлений
сохранён и исключает дублирование строк:

1. `fail > 0` → ровно одна строка `ALERT Tuber-Telegram: сбор не удался — …` (как было);
2. иначе `err >= 3` или (`ok > 0` и `err * 100 // ok >= 5`) → строка `… повторные ошибки сети при сборе — …` (как было);
3. иначе `ok == 0` → ровно одна строка
   `ALERT Tuber-Telegram: сбор не взял ни одного канала — каналов ок 0, сбоев <fail>, ошибок <err>, новых <new>, обновлено <upd>.` (**новое**);
4. иначе (`ok > 0`, ошибки ниже порогов) → тишина (как было).

Благодаря порядку: при `ok=0` и `fail>0` срабатывает ветка 1 (нет дубля про «ни одного канала»);
при `ok=0` и `err>=3` — ветка 2 (тоже без дубля). Строка про флуд аккаунта по-прежнему
печатается дополнительно и независимо.

`collect.py` не менялся, рабочая база не менялась, cron-задания не трогались.

## Рекомендация

Ветка `ok == 0` срабатывает и при штатном полном пропуске из-за дедлайна — это
намеренно: при 155 каналах пустой сбор всегда требует внимания владельца.
Если в будущем появится причина легитимного пустого прогона (например, массовая
отписка), стоит отличать её явным полем в JSON от `collect.py`, а не ослаблять
это правило.
