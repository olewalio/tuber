# ТЗ-41. Читаемая выдача отчёта: Markdown-мастер и DOCX-экспорт

Дата: 18.09.2026. Проект: /root/tuber. Основание: владелец получил полный отчёт
(`reports/report-2026-09-18.txt` → .docx) и сказал дословно: «сформируй мне читаемо.
Сейчас это невозможно читать глазами». Текст отчёта — плоский: абзацы, отступы
пробелами, поля в одну строку через `;`, ссылки в конце строки. Глазами это нечитаемо.

## 1. Цель

Полный отчёт должен уметь отдаваться читаемым документом: **заголовки разделов и
блоков, каждый пункт — отдельным абзацем с жирным заголовком, поля пункта —
отдельным списком, ссылка — отдельной строкой, оговорки — списком.** Формат
выдачи: Markdown-мастер (`.md`) и DOCX (`.docx`). Текстовый отчёт (`build()`) и
компактная сводка (`build_compact()`) обязаны остаться БАЙТ-В-БАЙТ теми же.

### 2.1 Формат строк отчёта (реальные примеры, отступ = 3 пробела)

```
1. YouTube — топ по просмотрам в сутки за окно.
   Правило: окно 20886 видео с замерами; отсечка показов 50 000 (не-ru) / 10 000 (ru, lang='ru'); ранжирование по views_per_day убыв.
   Grok Bot за $20: девять сценариев использования — канал Paul J Lipsky; просмотры/сутки 1 912 008, просмотры 5 789 413, лайки 9 116; https://www.youtube.com/watch?v=UyMJBUCyDIs

5. Виральные — охват против своей аудитории.
   Метрика: охват = просмотры ÷ подписчики СВОЕГО канала ...
   Свежесть: во ВСЕХ блоках материал должен быть опубликован внутри окна отчёта ...
   Блок 1. YouTube — полезное (подписчиков ≥ 1 000, просмотров ≥ 5 000, охват ≥ 3.0; ...).
   Блок 1: рассмотрено 20886, прошло полы 102, показано 15.
   Завод TerraFab утроит выпуск чипов для ИИ — канал Rayan Miller | Crypto & News; подписчиков 1 140, просмотров 499 494, в сутки 7 892, охват на подписчика 438.15, кратность к норме канала 106.9 (норма 4 671); опубликовано 8 дн. назад; тема: чипы и железо, язык en; https://www.youtube.com/watch?v=PrYfoYKqR24

      3.1. YouTube: просмотров ≥ 50 000, по просмотрам убыв.
   3.1: рассмотрено 20886, прошло полы 106, показано 5.
   Unitree открывает исходный код модели UnifoLM-WLA-1.0 ... — канал ...; просмотров 3 522 093, ...; https://...

ПОДВАЛ: честные оговорки (что в данных неполно)
   YouTube: viral_index пуст у 95721 из 121668 строк score — ...
```

Итого распознаваемые виды строк:
1. заголовок раздела: колонка 0, `^\d+\. ` ;
2. шапка отчёта: первые три строки (заголовок, «окно: …», `=`*72);
3. заголовок блока: отступ 3, `^   Блок \d+\. ` ;
4. статистика блока: отступ 3, `^   Блок \d+: рассмотрено (\d+), прошло полы (\d+), показано (\d+)\.` ;
5. заголовок под-блока: отступ 6, `^      \d+\.\d+\. ` ; статистика под-блока: отступ 3, `^   \d+\.\d+: рассмотрено … показано (\d+)\.` ;
6. пояснение: отступ 3, `^   (Правило|Метрика|Свежесть|Оговорка|Границы):` ;
7. пункт: отступ 3, всё остальное непустое (может быть и «нет постов по темам …» — заглушка при `показано 0`, отступ 8);
8. подвал: колонка 0 `ПОДВАЛ: …` + пункты с отступом 3.

## 3. Что сделать

### 3.1 Новый модуль `tuber/analysis/readable.py`

* `parse_report(text: str) -> ReportDoc` — разбор текста полного отчёта по правилам §2.1
  в дата-классы: `ReportDoc(header: list[str], sections: list[Section], footer: Section)`,
  `Section(title: str, number: int, notes: list[str], blocks: list[Block])`,
  `Block(title: str, stats: str, shown: int, items: list[Item])`,
  `Item(text: str, fields: list[str], link: str | None)`.
  Числовые поля (`views`, `likes`, `reach`, `ratio`) выделять не требуется.
* Разбор пункта: `segments = line.split("; ")`; с конца забираются сегменты, начинающиеся
  с известного поля (`канал `, `подписчиков `, `просмотров`, `просмотры`, `в сутки`,
  `лайки`, `ответы`, `опубликовано`, `тема:`, `язык`, `кратность`, `норма`, `охват`,
  `база канала`, `значимость`, `https://`, `http://`). Остаток — текст пункта. Затем, если
  текст содержит ` — ` И правый кусок начинается с метрики, правый кусок переносится в поля
  первым (кейс `@sama: … — лайки 3 831, ответы 921`). Ссылка — сегмент, начинающийся с `http`.
* **Самопроверка обязательна:** число разобранных пунктов блока обязано совпасть с
  `показано N` из строки статистики; расхождение — не «пропустить», а поднять
  `ValueError` с указанием блока и чисел. Непонятая строка (не подошла ни под один вид) —
  тоже ошибка (лучше падение, чем тихая потеря пункта).
* `render_markdown(doc: ReportDoc) -> str` по макету §3.3.
* `render_docx(doc: ReportDoc, path) -> None` — через `python-docx`, оформление §3.4.
  Ссылки — настоящие гиперссылки (`add_hyperlink`, в python-docx 1.2.0 есть; если нет —
  собрать `w:hyperlink` вручную), текст ссылки = полный URL.
* Модуль не ходит в сеть, не пишет в боевую БД, не импортирует ничего вне текущих зависимостей
  (`python-docx` уже установлен; новых зависимостей не добавлять).

### 3.2 CLI (`main` в `report.py`)

* `--readable PATH` — записать Markdown-мастер;
* `--docx PATH` — записать DOCX (если `--readable` не задан, мастер собирается во временный файл и удаляется);
* оба флага работают вместе с `--save`, `--compact`, `--json`; при `--json` флаги игнорировать;
* в ветке `--compact` (владельцу) ничего лишнего в stdout не печатать — служебные строки только в stderr;
  путь к записанному docx добавлять одной строкой в конец txt-файла полного отчёта НЕ надо (текст отчёта неизменяем).
* код возврата: 0 при успехе; при ошибке разбора — `2`, сообщение в stderr, txt-вывод по-прежнему печатается.


Правила макета: заголовок документа — H1; разделы — H2 (`## N. Название`); блоки внутри
раздела «Виральные» — H3; под-блоки 3.x — H4; пояснения курсивом; пункт — нумерованный
абзац с ЖИРНЫМ заголовком (`**N. …**`); поля — маркированные строки; ссылка — последняя
строка пункта. Никаких «=====» и отступов пробелами в мастере.

### 3.4 Оформление DOCX (скучное и читаемое, как принято у владельца)

* шрифт Calibri 11, цвет текста чёрный, никаких цветных заголовков, без колонок и таблиц;
* H1 16 pt bold, H2 14 pt bold (перед каждым разделом — разрыв страницы), H3 12 pt bold, H4 11 pt bold;
* пояснения — курсив 10 pt; шапка — 10 pt;
* пункт: абзац «N. » жирным + текст пункта обычным; поля — список с «• », отступ 0.6 см;
* ссылка — отдельная строка-гиперссылка обычным шрифтом (не «синий подчёркнутый по умолчанию» — допустимо,
  если не получается иначе; главное — кликабельность);
* поля страницы 2 см; после каждого пункта — пустой абзац-разделитель 6 pt.

### 3.5 Обёртка `scripts/common/tuber_report.sh`

После успешной сборки отчёта — дополнительный вызов того же интерпретатора:

```
"$TUBER_PYTHON" -m tuber report --save --out "$REPORTS_DIR" \
    --readable "$REPORTS_DIR/report-$(date -u +%F).md" \
    --docx     "$REPORTS_DIR/report-$(date -u +%F).docx" >/dev/null 2>>"$LOG"
```

Условия: stdout обёртки (то, что уходит владельцу) не меняется; падение этого шага не влияет
на код возврата и не печатает ALERT; `--days`/`--db` из окружения учитываются так же, как в основном вызове;
в лог попадает строка о результате (`docx: <путь>, N пунктов` или ошибка).
