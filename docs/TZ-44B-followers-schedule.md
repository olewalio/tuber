# ТЗ-44B: суточное задание снимков подписчиков X на сессии

Дата: 21.09.2026. Один коммит: `ТЗ-44B: суточное задание снимков подписчиков X`.
Проверка шла на копии боевой базы (`/tmp/fw_copy.db`); боевая `data/tuber.db` не
писалась.

## Что сделано

1. **Обёртка** `scripts/x/tuber_x_followers.sh` (по образцу обёрток ТЗ-7/ТЗ-11):
   * суточный бюджет сессии — `TUBER_X_SESSION_DAILY_CAP` (env), иначе из
     `config.X_SESSION_DAILY_CAP` (по умолчанию 800);
   * `--limit` = `min(реестр, остаток суточного бюджета, TUBER_X_FOLLOWERS_LIMIT)`.
     Остаток считается по журналу `transport_request` за 24 ч (`store.session_budget`);
   * обход идёт **порциями по остатку окна** (`X_SESSION_WINDOW_CAP=50` за 900 с):
     транспорт сам поднимает `XSessionRateLimited` при исчерпании окна, поэтому
     один вызов CLI на 216 аккаунтов прервался бы на 50-м. Порция = остаток окна,
     между порциями обёртка ждёт освобождения окна; ротация в CLI
     (`subs IS NULL DESC, subs_at ASC`) подставляет следующие аккаунты;
   * при норме МОЛЧИТ (журнал `/root/.hermes/logs/tuber_x_followers.log`);
   * при отказе/cooldown/blocked — одна строка `ALERT` по-русски; при
     исчерпанном суточном бюджете — `skipped: budget exhausted` в журнал, без
     уведомления. Всегда код 0.
2. **Регистрация** в `scripts/install_hermes_cron.sh`: новый шим в `LAUNCHERS` и
   запись в `NEW_JOBS` —
   `tuber_x_followers.sh:10 2 * * *:Tuber-x: подписчики (сессия X)`.
   Выбрана группа `NEW_JOBS` (а не `JOBS`), потому что задание новое и его
   регистрирует владелец: общая проверка установщика тогда сама печатает
   «ожидает регистрации владельцем», а не считает его расхождением.
3. **Документация**: раздел про `followers` в `docs/x/docs/schedule-tz4.md`
   (зачем, чем ограничено, что делать при 429).

## Время: 2:10 МСК, почему

* свободная минута `:10` (занятые X-заданиями минуты `:00`, `:05`, `:20`,
  `:30`, `:40`, `:50`);
* не пересекается с `сбор тира A` (`:00`), `метрики` (`:05`), `полный текст`
  (`:20`), `сюжеты` (`:40 */2`), `полный снимок ленты` (4:40), `дискавери`
  (4:50), `бэкап` (5:00), `суточный цикл`/`отчёт` (7:00);
* обход ~216 аккаунтов занимает ~1–1.5 ч (5 порций по 50 с ожиданием окна),
  поэтому окно 2:10–3:50 не задевает утренний блок 6:00–8:00 и бэкап 5:00;
* единственный другой потребитель сессии X — `enrich` в `:05`; старт в `:10`
  сразу после него минимизирует конкуренцию за окно.
