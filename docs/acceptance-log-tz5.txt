[12] Справедливое распределение мест в сводке (ТЗ-5-доп-3, 17.09.2026)
-------------------------------------------------------------------
Дефект доп-2: сводка обрезалась «с конца», поэтому последний раздел терял
пункты первым и на живой базе уходил целиком:
  «3. Telegram — топ постов за окно:
     все пункты скрыты: не хватило лимита знаков. скрыто пунктов: 36».
Единая выдача задумана как ОДИН отчёт по трём платформам — сводка без Telegram
этой задаче не отвечает («полный список в файле» не помогает: владелец читает
чат).

Закрыто: build_compact делит бюджет справедливо. Резерв — каждый раздел с
данными получает минимум 1 пункт; остаток бюджета раздаётся round-robin: по
одному следующему пункту за шаг, пока пункт влезает целиком; порядок внутри
раздела сохраняется (сначала верхние). Если резерв не влезает, укорачивается
только ОПИСАНИЕ пункта (CompactItem: head|desc|tail; с многоточием) — ссылка и
цифры неприкосновенны. Строка «все пункты скрыты» больше не печатается:
раздел без данных честно сообщает «нет данных за окно». Счётчики скрытых
печатаются всегда, и «показано + скрыто» сходится с полным отчётом.

Все замеры — на КОПИЯХ боевой базы; боевая data/tuber.db не открывалась на
запись (только штатный read-only `tuber db backup`):
  копия A: data/backups/tuber-20260917-084822.db
  копия B: <tmp>/tuber-20260917-090329.db (свежая копия боевой)

[12a] Правило распределения мест
  1) резерв: каждый непустой раздел получает минимум 1 пункт;
  2) round-robin: остаток — по одному следующему пункту за шаг, пока влезает;
  3) не влез резерв → укорачивается только ОПИСАНИЕ (с многоточием),
     ссылка и цифры не меняются;
  4) счётчики скрытых по каждому разделу печатаются всегда;
  5) «все пункты скрыты» — запрещено; нет данных → «нет данных за окно».
