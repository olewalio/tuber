# Tuber_OS — разведка механик (этап 2, 10.09.2026)

Источники — внешние (внизу ссылки) и код старого контура (раздел 4, отдельный аудит).

## 1. Главный вывод разведки: тренд — это не просмотры, а скорость

Профессиональные инструменты (vidIQ, OutlierKit) и разборы алгоритма YouTube сходятся
в одном: **самые просматриваемые видео и самые растущие видео — разные множества.**

- Видео с 1 млн просмотров за два года может набирать 2 просмотра в час — это мёртвый груз.
- Видео с 50 тыс. просмотров, набирающее 150 в час — живой тренд.
- Видео с 5 тыс. просмотров за час — вспышка.

Метрика, которая это ловит, называется **VPH (views per hour)** — просмотров в час,
и её дневной эквивалент **VPD (views per day)**. В нашем случае источник —
два и более замера метрик во времени: `VPD = (просмотры₂ − просмотры₁) / дни`.

Второй инструмент — **Outlier Score**: во сколько раз видео обошло *свой канал*:
`outlier = просмотры видео / медиана просмотров канала` (с поправкой на возраст видео
и размер канала). Диапазоны, принятые в индустрии:

| Балл | Что значит | Как использовать |
|---|---|---|
| < 2x | в пределах нормы канала | в отчёт не берём |
| 3x+ | значимый выброс | ядро SEO-сборника |
| 5x–10x | сильный выброс | приоритет разбора |
| 10x+ | аномалия (проверить на накрутку) | разбирать руками |

Ценность outlier в том, что он **сравнивает каналы разного размера**: 3x у канала
с 5 тыс. подписчиков и 3x у канала с 5 млн — сопоставимые события. Это ровно
механика блока «тёмные лошадки».

## 2. Что реально влияет на продвижение (для SEO-сборника)

Разбор алгоритма (techspurblog, 2026) даёт список сигналов, важnych для сборника:

1. **Удержание и время просмотра** — сильнейший сигнал, но для чужого видео
   недоступен (это данные кабинета владельца).
2. **CTR (кликабельность)** — определяется заголовком и обложкой. Тоже недоступен
   для чужого видео, но **его можно оценить косвенно**: лайки/просмотры,
   комментарии/просмотры, скорость роста при известном размере канала.
3. **Вовлечённость** — лайки, комментарии, репосты. Комментарии весят
   непропорционально много: они означают активную, вовлечённую аудиторию.
   **Ранняя вовлечённость (первый час) весит больше** поздней.
4. **Релевантность** — заголовок, описание, произносимый текст.

Вывод для сборника: раз мы не видим CTR и удержание чужого видео, собираем всё,
что видно (заголовок, обложка, описание, теги, длительность, время выхода,
лайки, комментарии, скорость), и строим **прокси-показатели**:
лайков на 1000 просмотров, комментариев на 1000 просмотров, VPD, outlier.
Проценты CTR в отчёте не показывать — мы их не знаем, а выдуманная цифра хуже
отсутствующей.

## 3. Следствия для ранней вовлечённости и расписания замеров

Сигнал «первый час» означает: свежие видео (моложе 48 часов) надо мерить чаще,
чем старые. Старым достаточно одного замера в сутки.

Предлагаемое расписание замеров (уточняется после расчёта квоты):

- видео моложе 48 часов — замер каждые 3–4 часа (6–8 замеров в сутки);
- видео 2–10 дней — замер 2 раза в сутки;
- видео старше 10 дней — 1 замер в сутки (нужен для контроля «долгоживущего роста»).

## 4. Что доступно по чужому видео через YouTube Data API v3

| Что нужно для сборника | Доступно? | Откуда |
|---|---|---|
| просмотры, лайки, комментарии | да | `videos.list` part=statistics |
| заголовок, описание, теги, категория, язык | да | part=snippet |
| длительность, определение, пометка про субтитры | да | part=contentDetails |
| темы видео (topicDetails) | да | part=topicDetails |
| пометки статуса (например, «для детей», лицензия) | да | part=status |
| обложка (ссылка на картинку) | да | snippet.thumbnails |
| подписчики и размер канала | да | `channels.list` part=statistics |
| средние просмотры канала (база для outlier) | нет напрямую | считаем сами по uploads канала |
| CTR (кликабельность) | **нет** | только кабинет владельца |
| удержание / время просмотра | **нет** | только кабинет владельца |
| источники трафика (поиск/рекомендации) | **нет** | только кабинет владельца |

Итог: база для outlier и VPD строится **собственными замерами**, а не запрашивается.
Это принципиально: механизм обязан копить историю, иначе метрик роста не будет.

## 5. Что берём и что не берём

**Берём:**
- VPD (просмотров в сутки) как основную метрику роста;
- outlier score как метрику «относительно своего канала»;
- комментарии на 1000 просмотров как метрику обсуждения;
- медиану просмотров канала как базу сравнения;
- частые замеры свежих видео (первый час весит больше);
- сбор заголовков/описаний/тегов/обложек как SEO-сырьё.

**Не берём:**
- keyword-подход «ИИ или не ИИ» из старого контура (он ловит мемы; нужен смысловой разбор);
- формулу «просмотры / подписчики» без порогов (даёт абсурд у микро-каналов);
- CTR и удержание в отчёте (данных нет — рисовать нельзя);
- поиск по каналам как основной способ (ловушка: search по каналам отдаёт свежесозданные микро-каналы).

## 4. Старый контур (`/root/.hermes/scripts/viral/`): что берём, что нет

Полный аудит — `AUDIT-OLD-CONTOUR.md` (34 дефекта с адресами файл:строка).
Здесь только выводы для нового механизма.

**Главное: роста в старом контуре нет.** Единственная попытка — `growth_bonus`
(`capture_snapshots.py:129-141`), и она построена на отношении **кумулятивных средних**
(все просмотры ÷ весь возраст видео), а не на дельте между замерами. Интервал между
замерами в расчёт не входит. Результат из базы: из 22 442 замеров `growth_bonus`
отрицательный в 18 347 (82%), положительный в 1 924. Метрика систематически штрафует
почти все видео. Колонок `delta_views` / `delta_likes` / `delta_comments` в схеме нет.
В публикуемом дайджесте динамика не выводится вообще — только абсолютные числа.

**Что берём механикой (без копирования кода):**
- транспорт YouTube API с ротацией ключей и живой проверкой годности (`yt_utils.py:38-149`) — эта часть работает;
- поиск «видео-first» с пейджингом и дешёвым предфильтром до дорогого `videos.list` (`discover_videos.py:319-394`);
- обход uploads-плейлистов с остановкой по возрасту видео (`scan_videos.py:89-133`);
- идею отдельной таблицы замеров с историей (`capture_snapshots.py:182-195`) — сама идея верна, реализация расчёта нет;
- абсолютные пороги виральности и кап на вовлечённость (`capture_snapshots.py:112-148`) — защита от накрутки;
- текстовые фильтры спама: штраф за чужие алфавиты (`ai_classifier.py:112-131`).

**Что делаем иначе (и почему):**

| Ошибка старого контура | Как в Tuber_OS |
|---|---|
| рост = отношение средних, интервал не учтён | дельта между замерами с реальным интервалом (`AUDIT-OLD-CONTOUR.md:129-141`) |
| замеры 2 раза в сутки → нет скорости на взлёте | свежие видео (до 48 ч) — каждые 3–4 часа |
| outlier-оценки нет, только `log10(views/subs)` | медиана просмотров канала + outlier score |
| обложка не пишется в части путей (884 видео без картинки) | обложка — обязательное поле на входе, качество maxres с проверкой доступности |
| теги в двух форматах (757 запятой / 519 пробелом / 858 пусто) | один формат, одна точка записи |
| разбор обложек — 8 штук за цикл, всего 25 за 41 цикл | лимит по цене, а не по «8»: замер дал ~$0,00027 за обложку |
| классификатор «ИИ» — подстрочный матчер слов | смысловой разбор, а не словарь |
| нет часа публикации, нет тем канала, мёртвые колонки каналов | тайминг и темы — обязательные поля SEO-сборника |
| ошибки публикации без обработки: 400 от Telegram → цикл завершается с кодом 0, алерт молчит | публикация идемпотентная, ошибка видна |

**Стоимость разбора обложек (замер 10.09.2026, живой вызов):** $0,00019–0,00036 за обложку,
в среднем ~$0,00027. То есть 200 обложек в сутки ≈ $0,054/сутки ≈ $1,6/месяц.
Ограничение «8 обложек» в старом контуре — не про цену, а про кривую выборку.
Ещё деталь: 60–95% оплачиваемых выходных токенов уходит в **скрытый reasoning**,
а не в текст описания — для разбора обложек это чистый перерасход.
