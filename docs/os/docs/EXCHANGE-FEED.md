# Договор формата фида-моста (EXCHANGE-FEED)

**Статус:** обязателен для трёх проектов — `tuber-os`, `tuber-telegram`, `tuber-x`.
Дата введения: 15.09.2026 (ТЗ-19). Версия формата: **2** (15.09.2026, ТЗ-21).
Канон — в `tuber-os`; в двух других проектах лежит копия этой страницы.

Файл-мост — единственный согласованный способ передачи внешних кандидатов между
проектами. Один проект **производит** файл, другой **потребляет**. Договор
описывает оба конца стыка, и **обе стороны обязаны его соблюдать**.

> **Формат ломать нельзя без одновременной правки обоих проектов.**
> Меняешь состав или смысл полей — сначала правишь этот документ, потом
> производителя и потребителя, и только потом выкатываешь. Односторонняя правка
> (потребитель перестал понимать поле производителя или наоборот) — это разрыв
> стыка; именно на таком разрыве держался дефект D-12 из `docs/TECH-DEBT.md`.

## 1. Формат файла

- **JSONL**: один JSON-объект на строку, разделитель — `\n`.
- Кодировка — **UTF-8** (для русского текста допустим `ensure_ascii=False`).
- Пустые строки игнорируются (не считаются за записи).
- Порядок строк на смысл не влияет.
- Потребитель обязан быть **толерантным**: оборванная/битая строка (например, у
  производителя упал писатель) не должна блокировать приём всего файла. Битая
  строка пропускается и считается.

## 2. Поля

### Обязательные (есть в каждой строке)

| Поле | Тип | Смысл |
|------|-----|-------|
| `kind` | строка | Род кандидата: `telegram`, `x` или `youtube`. |
| `handle` | строка | Для `telegram`/`x` — имя канала/аккаунта. Для `youtube` — ссылка на видео или его id. |

### Необязательные (могут отсутствовать)

Типы полей обязательны (ТЗ-21): `videos` — **число**, а не список; `examples` —
список **строк**, а не объектов. Числа (`mentions`, `videos`) всегда пишутся
числом; список id видео идёт отдельным полем `video_ids`.

| Поле | Тип | Смысл |
|------|-----|-------|
| `mentions` | **число** | Сколько раз кандидат встретился в источниках. |
| `videos` | **число** | Из скольких РАЗНЫХ видео/постов пришёл кандидат. |
| `video_ids` | **список строк** | Идентификаторы этих видео (у Telegram-фида — реальные id, если известны, иначе `[]`). |
| `sources` | список строк | Идентификаторы источников упоминаний. |
| `source` | строка | Метка продюсера, напр. `tuber-os:video-descriptions`, `tuber-telegram:posts`. |
| `examples` | **список строк** | Цитаты-примеры (не объекты). |
| `ai_hint` | 0/1 | Есть ли рядом с кандидатом ИИ-признак. |
| `first_seen` | строка ISO 8601 UTC | Первое появление кандидата (`YYYY-MM-DDThh:mm:ssZ`). |
| `last_seen` | строка ISO 8601 UTC | Последнее появление кандидата. |
| `video_id` | строка, 11 символов | Только для `kind=youtube`; id видео. |

## 3. Правила производителя

- `handle` — **всегда без `@`**, в **нижнем регистре**, **без завершающего слэша**.
- Для `kind=telegram`/`x` поле `handle` — это имя (например `alphachannel`), а не
  ссылка.
- Для `kind=youtube` поле `handle` — это **ссылка на видео** (или голый
  11-символьный id); дополнительно допускается явное поле `video_id`.
- Пиши только те поля, которые определены выше; лишние поля допустимы, но
  потребитель на них не рассчитывает.
- `videos` пиши **числом**, `examples` — **списком строк**. Старый фид
  tuber-telegram писал `videos` списком и `examples` объектами; такие строки
  потребитель обязан принять (см. п.4), но новые файлы так не пишутся.
- Не изменяй формат полей без правки обоих проектов (см. шапку).

## 4. Правила потребителя

- Неизвестный `kind` — **игнорировать строку, но считать** её (счётчик
  `skipped_kinds`).
- Отсутствующий `handle` — строка **негодная** (считается битой).
- Для `kind=youtube` id берётся **по порядку полей** (первое сработавшее):
  `video_id` → `id` → `url` → `link` → `video_url` → `handle`. Каждое из них
  принимается и как ссылка (`youtube.com/watch?v=…`, `youtu.be/…`), и как голый
  11-символьный id.
- **Терпимость к обеим версиям поля** (ТЗ-21): `videos` принимается и числом, и
  списком (список трактуется как перечень id); `video_ids` читается, если есть;
  `sources` принимается списком, строкой или отсутствующим (тогда берётся
  `source`); `examples` — списком строк, списком объектов (у объекта берётся
  `text`) или одиночной строкой.
- Негодное значение поля (чужой тип) — **не падение**: строка считается в
  счётчике `bad_fields`, импорт продолжается.
- Битая строка — пропустить, увеличить счётчик `bad_lines`, продолжить импорт.
- Отменить импорт целиком и выдать понятную ошибку (без трейсбека) можно
  **только** если файл не найден/нечитаем, **пуст**, или **все** строки битые.

## 5. Пример (по одной строке на каждый `kind`)

```json
{"kind": "telegram", "handle": "alphachannel", "mentions": 12, "videos": 7, "video_ids": [], "ai_hint": 1, "source": "tuber-os:descriptions", "first_seen": "2024-11-05T00:00:00Z", "last_seen": "2025-01-02T00:00:00Z", "examples": ["dQw4w9WgXcQ: Подпишись: t.me/AlphaChannel"]}
{"kind": "x", "handle": "someuser", "mentions": 3, "videos": 2, "video_ids": ["abcdefghijk", "lmnopqrstuv"], "ai_hint": 0, "source": "tuber-os:descriptions", "first_seen": "2024-11-05T00:00:00Z", "last_seen": "2024-11-05T00:00:00Z", "examples": ["abcdefghijk: мы в x.com/SomeUser"]}
{"kind": "youtube", "handle": "https://www.youtube.com/watch?v=dQw4w9WgXcQ", "video_id": "dQw4w9WgXcQ", "ai_hint": 1, "source": "tuber-telegram:posts", "first_seen": "2024-12-01T00:00:00Z", "last_seen": "2024-12-01T00:00:00Z"}
```

## 6. Совместимость

- Формат версии **1** введён 15.09.2026 (ТЗ-19). Изменения состава полей или их
  смысла — только через правку этого документа и обоих проектов.
- Версия **2** (15.09.2026, ТЗ-21): поле `videos` закреплено как **число**,
  добавлено `video_ids` (список строк), `examples` — список **строк**. Старые
  файлы (где `videos` — список, `examples` — объекты) потребитель обязан
  принимать: импортёры ничего не перезаписывают задним числом.
- Импорт в `tuber-os` реализован в `tuber/candidates.py` (`_parse_feed`,
  `_video_id_from_entry`, `_bad_field_count`); экспорт — `tuber/candidates.py`
  (`export_external`). Потребитель в tuber-x — `tuber_x/feeds.py`; в
  tuber-telegram — `scripts/bridge_common.py` (`read_feed`, `feed_examples`).
