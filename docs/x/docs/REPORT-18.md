## 2. Команда

```
python -m tuber_x.cli import_candidates --feed <путь.jsonl> [--feed ...] [--limit N] [--dry]
```

* берутся только строки `kind="x"`; чужой `kind` считается в `skipped_kinds`;
* битая строка JSON считается в `bad_lines`, импорт продолжается;
* отсутствующий файл — не ошибка, попадает в `feeds_missing`;
* ошибка (код 2) — только пустой файл или файл, где ВСЕ строки битые;
* `--limit` по умолчанию 500 (`config.FEED_IMPORT_LIMIT`), сортировка
  `mentions` desc → `videos` desc → `ai_hint`;
* `--dry` считает всё, но откатывает транзакцию (в базу не пишет);
* stdout — ровно один JSON с ключами `feeds`, `feeds_missing`, `imported_new`,
  `merged`, `skipped_filter`, `skipped_limit`, `queue_total`, `dry`.

**Слияние с существующим кандидатом (по `handle`).** `seen_count += mentions`;
`distinct_sources` пересчитывается как длина объединённого списка источников
`feed:<фид>:src:<канал>` и `feed:<фид>:video:<id>` (учитываются оба поля фида,
`sources[]` и `source`); `first_seen_at` = минимум, `last_seen_at` = максимум;
`found_via` дополняется значением фида (`yt_desc:tuber-os`, `tg_posts:tuber-telegram`)
без дублей; `feed_source` — теги фидов через запятую, без дублей; `ai_hint` = OR;
`priority` пересчитывается существующей `registry.candidate_priority`.

**Никогда не меняются** `validated`, `reject_reason`, `verified_at`, `llm_checked`.
`reject` остаётся `reject`, `ok`/`provisional` не понижаются. Новые кандидаты
создаются с `validated=NULL`, `verified_at=NULL` (как в дискавери).

**Порог упоминаний** взят из существующего конфига фильтра проекта —
`VERIFY_MIN_MENTIONS = 2` (Р4.3.2); значение не менялось.

**Сети нет.** Приём только наполняет очередь: верификация (120 запросов/сутки,
30 проверок/сутки) этим ТЗ не запускается.

## 7. Что нашлось по дороге

1. **`feed_tag` брал не тот каталог.** Первая версия извлекала проект из пути
   сдвигом на три уровня и для `/root/tuber-telegram/...` давала `root` вместо
   `tuber-telegram`. Поймано на живом фиде (в `feed_source` попадал `root`).
2. **`foxnews` уже в реестре.** Гигант-новостник отсеивается как
   `already_registered`, поэтому счётчик `news_giant` меньше, чем число
   фактических гигантов в фиде. Порядок фильтров оставлен сознательно.
3. **Живой фид `tuber-os` отсутствует.** YouTube-описания в приёме не
   участвуют; `feeds_missing` это фиксирует, но фактический приток из описаний
   проверить не на чем.
4. **`ai_hint` из Telegram-фида всегда 0.** Колонка заведена и заполняется, но
   единственный доступный источник её не подтверждает; положительный сигнал
   ждём из YouTube-фида.
5. **Боевая база мигрировала во время работы.** Это сделал живой сторож
   (аддитивная миграция), а не приёмка; счётчики и данные не тронуты. Урок:
   миграцию схемы применяет первый запущенный процесс проекта, поэтому проверять
   её безопасность нужно на копии заранее (что и сделано).

## 8. Ограничения и рекомендации

1. **Приём не поставлен в расписание.** ТЗ-18 запрещает трогать cron-задания,
   поэтому `import_candidates` пока ручная команда. Рекомендация: добавить
   суточный прогон после сборки фидов (см. техдолг D-07).
2. **Порог упоминаний `VERIFY_MIN_MENTIONS=2` режет 108 из 152** строк (71%).
   Это осмысленно (одно упоминание — не подтверждение), но если у YouTube-фида
   упоминания считаются иначе, порог стоит пересмотреть отдельным ТЗ.
3. **`distinct_sources` после слияния растёт быстро** (один Telegram-фид даёт
   десятки ключей-каналов на хендл), что завышает `priority`. Существующая
   формула приоритета не менялась согласно ТЗ; это точка калибровки на будущее.
4. **Сводку читает владелец без пояснений**, но горизонт считает всю очередь,
   включая уже отклонённые/принятые кандидаты. Если нужно считать только
   `pending`, это отдельная правка.
