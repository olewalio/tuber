# HypeParser: что развёрнуто 07.10.2026

Документ описывает рабочее состояние, чтобы через месяц не разбираться заново.

## Что это

Страница поиска постов X по коэффициенту «просмотры / подписчики».
Коэффициент = просмотры поста, делённые на число подписчиков автора (×100).
Если подписчиков нет или пост без просмотров — коэффициент не считается.

## Адрес и вход

- Страница: https://<server_host>.sslip.io/hype/
- Логин: `hype`, пароль — в файле `/root/.hype_page_password` (права 600).
- Смена пароля:
  `printf 'hype:%s\n' "$(openssl passwd -apr1 'НОВЫЙ_ПАРОЛЬ')" > /etc/nginx/.htpasswd_hype`
- Открытый адрес `http://<server_host>/hype/` сам перебрасывает на шифрованный (301).
  Сертификат — Let's Encrypt на имя `<server_host>.sslip.io` (sslip.io резолвится
  в наш IP без настройки DNS). Срок до 05.01.2027, продлевается сам (таймер certbot,
  хук `systemctl reload nginx`). Для продления нужен доступен извне порт 80 — он открыт.

Пароль по открытому HTTP не ходит: вход только по TLS, страница закрыта паролем,
закрыта от поисковиков (`X-Robots-Tag: noindex`), ограничена по частоте
(30 запросов/мин с адреса, запас 10).

## Как устроено

- Приложение: `tuber/tuber/platforms/x/hype_web.py` (только стандартная библиотека;
  слушает **только** `127.0.0.1:8730` — снаружи к нему не подключиться.
- Служба: `tuber-hype.service` (включена, переживает перезагрузку,
  `Restart=always`). Интерпретатор — питон проекта
  `/usr/local/lib/hermes-agent/venv/bin/python3` (у него есть нужные библиотеки;
  системный python их не имеет и поиск молча сломался бы).
  Важно: этот путь — копия одного и того же venv, что и у боевого сбора X.
- Наружу отдаёт nginx:
  - `sites-enabled/zz-hype.conf` → `sites-available/hype.conf` (блоки :80 и :443);
  - `snippets/hype-shared.conf` (общая часть: пароль, частота, прокси);
  - `conf.d/hype-zone.conf` (зона ограничения частоты — объявляется внутри `http{}`).
  Симлинк назван `zz-hype.conf`, чтобы блок читался ПОСЛЕ `prop-rate` и не стал
  сервером по умолчанию для :80 (иначе перехватит чужие домены).
- Источники всех этих файлов лежат в репозитории: `deploy/`.

## Границы расхода запросов к X

- Один поиск за раз, пауза между поисками 10 с, не больше 5 страниц и 200 постов.
- Суточный потолок поисков — 100 (общий потолок аккаунта 1000/сут,
  расход виден в `GET /healthz`: поле `search_daily`).
- Кэш одинакового запроса — 10 минут.

## Как выключить или снять

- Остановить: `systemctl disable --now tuber-hype`
- Убрать страницу из nginx: `rm /etc/nginx/sites-enabled/zz-hype.conf && nginx -t && systemctl reload nginx`
- Полностью убрать: плюс `rm /etc/nginx/conf.d/hype-zone.conf /etc/nginx/snippets/hype-shared.conf /etc/nginx/.htpasswd_hype`

## Проверка, что всё живо

```
systemctl is-active tuber-hype                      # active
curl -s -u hype:$(cat /root/.hype_page_password) \
     --resolve <server_host>.sslip.io:443:127.0.0.1 \
     https://<server_host>.sslip.io/hype/healthz   # {"status": "ok", ...}
tail -5 /var/log/nginx/hype.access.log               # кто заходил
journalctl -u tuber-hype -n 20                       # журнал приложения
```
